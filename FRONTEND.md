# Фронтенд

Экраны и поведение веб-морды. Все поля и эндпоинты — в [API.md](API.md), общий контекст — [README.md](README.md).

## Главное для фронта

**Что за продукт.** Банк выдал кредит на строительство дома. По проекту к определённой дате должна быть определённая стадия. Дрон снимает участок, система сравнивает проект с фактом и, если стройка отстаёт или строят не то, поднимает тревогу **до того**, как клиент перестанет платить. Сотрудник банка видит тревогу, смотрит доказательства на фото и принимает меру.

**Главный вопрос интерфейса:** «по каким клиентам действовать сегодня и почему». Стадия и % — подробности.

**Договорённости с бэком:**

| # | Что | Как |
|---|---|---|
| 1 | Справочники | названия, цвета, стадии, уровни риска, сигналы, меры, материалы, ракурсы — **только из `GET /meta`**, ничего не хардкодим |
| 2 | Рамки на снимках | `bbox = [x1, y1, x2, y2]` в долях 0..1 от размера снимка; одинаково рисуются на превью и оригинале |
| 3 | Обработка облёта | после загрузки опрашиваем `GET /flights/{id}` раз в 2 с до `done` / `failed` |
| 4 | Два светофора | `risk_level` — риск клиента (главный, цветной); `data_status` — можно ли верить данным (иконка) |
| 5 | Ошибки | всегда `{"error": {"code", "message"}}`; `message` на русском, можно показывать как есть |
| 6 | Мок-режим | разработка против `MOCK=1` с первого дня; если `/meta.mock = true` — показываем плашку «Демо-данные» |
| 7 | Пользователь | на хакатоне без логина; имя передаём заголовком `X-User` |
| 8 | Ракурсы | 6 снимков: `N` `E` `S` `W` (фасады), `top_low` (дом сверху), `top_high` (участок сверху) |

**Справка по смыслу** (подробно в [BACKEND.md](BACKEND.md)):

| Уровень | Цвет | Что значит для пользователя |
|---|---|---|
| `green` | зелёный | всё по проекту, ничего делать не нужно |
| `yellow` | жёлтый | небольшое отставание, система сама назначила облёт раньше |
| `orange` | оранжевый | стройка встала, но клиент платит — **позвонить, пока не поздно** |
| `red` | красный | стройка стоит и есть просрочка, или строят не то — срочно, ручная проверка |

## 7. Фронт: экраны

Главный вопрос интерфейса: **«по каким клиентам надо действовать сегодня и почему»**. Стадия и % — подробности.

### 7.1 Лента тревог (стартовый экран)
- Карточки открытых тревог, сначала `red`, затем `orange`, затем `yellow`.
- В каждой карточке: адрес, цветной уровень риска, текст сигнала («По договору фундамент к 30.06, облёт 07.07: работ нет»), DPD, рекомендованная мера.
- Кнопки: «Принять меру», «Ложная тревога» (с причиной), «Открыть объект».
- Счётчики сверху: сколько объектов в каждом уровне.

### 7.2 Список объектов
- Таблица: адрес, кредит, **уровень риска**, стадия факт / план, отставание в днях, DPD, следующая контрольная точка, дата облёта, значок `data_status`.
- Фильтры: уровень риска, стадия, состояние данных, поиск.
- Сортировка по умолчанию: по риску, затем по отставанию.
- Кнопка «Добавить объект» (форма с графиком контрольных точек и проектными параметрами).

### 7.3 Карточка объекта
- **Шапка:** адрес, кадастр, кредит, уровень риска, `explanation` риска, рекомендованная мера с кнопкой.
- **План против факта** — главный блок:
  - график: плановая линия % по датам, точки облётов, отметки мер;
  - таблица контрольных точек: стадия, срок, состояние (`met` / `missed` / `unverified` / `upcoming`);
  - две колонки «По проекту» и «По облёту»: стадия, %, **материал стен** (с пометкой «закреплён по облёту от …»); позже этажность и площадь.
- **Материал стен:** кропы стен с каждого фасада в ряд, под каждым класс и уверенность; при расхождении с проектом — красная плашка и кнопка «Подтвердить / Ложная тревога».
- **Последний облёт:** стадия, %, уверенность, список элементов (найден / не найден / подразумевается), причины пересъёмки.
- **Галерея ракурсов:** 6 превью в порядке «участок → дом сверху → 4 фасада», с подписью ракурса. По клику — снимок крупно с рамками детекций. Рамки красятся по цвету класса, подпись — `label` и `conf`. Переключатель «показать рамки». Для `NOTHING_BUILT` крупно показывается `top_high` с наложенными границами участка из кадастра: пустой участок — главное доказательство.
- **Кнопки по облёту:** «Согласен», «Исправить» (стадия из `/meta`, %, комментарий), «На пересъёмку».
- Если есть правка человека, показывать её поверх результата модели с пометкой «исправлено: автор, дата». Результат модели остаётся доступным.
- **Журнал мер:** кто, когда, что сделал, результат.

### 7.4 Загрузка облёта
- Drag-and-drop 6 файлов: 4 фасада, сверху дом, сверху участок.
- Для каждого файла выпадающий список ракурса, по умолчанию «Авто (EXIF)».
- После отправки — экран «Обрабатывается» с опросом `GET /flights/{id}`, затем переход в карточку.

## 8. Мок-режим

Включается переменной `MOCK=1`. API отдаёт заготовленные данные из `mocks/` и не трогает модель. Моки покрывают все сценарии из раздела 4 — это готовый сценарий демо:

| Объект | План | Факт | DPD | Риск | Сценарий |
|---|---|---|---|---|---|
| obj_demo_1 | кровля к 30.11 | кровля, 60% | 0 | 🟢 | всё по графику |
| obj_demo_2 | стены к 30.09 | стены в процессе, 35%, отстаёт на 40 дней | 0 | 🟡 | лёгкое отставание → облёт раньше срока |
| obj_demo_3 | фундамент к 30.06 | **ничего нет** | 0 | 🟠 | **главный кейс демо:** звоночек до просрочки → звонок клиенту |
| obj_demo_4 | стены к 30.09 | стены, без прироста 3 месяца | 45 | 🔴 | стройка стоит + просрочка → soft collection |
| obj_demo_5 | транш на стены выдан | без прироста 70 дней | 0 | 🔴 | подозрение на нецелевое использование |
| obj_demo_6 | — | облёт с низкой уверенностью | 0 | — | `data_status: reshoot`, тревоги нет, назначен повторный облёт |
| obj_demo_7 | стены, газобетон | стены по графику, **брус** | 0 | 🔴 | часть 2: строят по графику, но не то → ручная проверка |

Загрузка облёта в мок-режиме тоже работает: через 3 секунды статус меняется на `done` и возвращается заготовленный результат. **Фронт разрабатывается против мока с первого дня, ML обучается параллельно.**

`GET /meta` отдаёт `"mock": true`, а фронт показывает плашку «Демо-данные».
