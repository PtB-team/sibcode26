# Как работает наш бэкенд

Наш модуль отвечает на вопрос: **«Из какого материала сделаны стены этого дома и на каких снимках это видно?»**

Команда ML обучает модель распознавать материалы. Мы делаем сервис, который принимает фотографии, вызывает готовую модель и превращает её ответы в удобный результат по дому.

## Пять шагов обработки

1. **Приняли фотографии.** Проверили, что это изображения подходящего формата и размера. Сохранили оригиналы и их контрольные суммы.
2. **Создали задание.** Записали в очередь: какой объект и какие снимки нужно обработать. Сразу сообщили приложению номер задания.
3. **Обработали отдельно.** Воркер забрал задание, создал превью и передал подходящие снимки модели. Верхние ракурсы не используются для определения материала стены.
4. **Объединили доказательства.** Проверили, согласуются ли ответы на разных фасадах. Повтор одного снимка или одного фасада не считается новым независимым подтверждением.
5. **Вернули результат.** Сохранили материал, показатель уверенности, причины проверки и участки снимков, на которых основан ответ.

API можно сравнить с приёмной: она принимает задание и сообщает его номер. Воркер — исполнитель, который разбирает фотографии. SQLite — журнал, в котором видно состояние задания и его результат.

Снимки нашего дрона имеют расширение JPG, но библиотека определяет их как MPO — JPEG-контейнер с несколькими кадрами. Для обработки используется основной кадр; дополнительные кадры и метаданные не удаляются из сохранённого оригинала. В ответе снимка есть `container_format` и `frame_count`.

## Почему иногда материала в ответе нет

| Состояние | Простыми словами |
| --- | --- |
| `model_unavailable` | Готовая модель ещё не подключена; это деморежим |
| `determined` | Есть согласованные результаты по материалу с нескольких подтверждённых фасадов |
| `hidden` | Стена закрыта отделкой или мембраной |
| `no_walls` | На доступных снимках модель не обнаружила стен для оценки |
| `insufficient_data` | Нет подходящих или достаточно уверенных наблюдений |
| `mixed` | Есть существенные признаки разных материалов; нужен человек |
| `needs_review` | Есть предположение, но не хватает подтверждений, не проверен целевой дом или результат расходится с сохранённым |

Например, снимки пустого участка или фундамента должны приводить к сообщению об отсутствии стен, когда это подтвердит модель. Фото оштукатуренного фасада не доказывает материал под штукатуркой. В папке `12` нужно подтвердить жилое здание по кадастру: адрес указывает на супермаркет, а обзор жилого объекта ограничен деревьями и ЛЭП.

GPS фотографии — полезная подсказка для привязки. Сам по себе он не подтверждает, какое из нескольких зданий в кадре является нашим объектом. Поэтому есть отдельное подтверждение `target_confirmed`.

## Что означает уверенность

Для первой версии берём наблюдения модели с уверенностью не ниже 0.6. Вес наблюдения — уверенность модели, умноженная на долю кадра, занятую стеной. Для одной пары «фасад — материал» используется только самое сильное наблюдение.

Итоговый показатель — минимум между долей голосов материала-победителя и средней уверенностью его наблюдений. Поэтому два слабых ответа не превращаются в «100% уверенности». Это рабочая оценка согласованности, а не измеренная вероятность правильного ответа.

Для автоматического закрепления материала нужны как минимум два разных фасада с известными ракурсами, показатель не ниже 0.8 и подтверждение нужного здания. Пороги 0.6, 0.8 и 0.35 для существенного второго материала — начальные настройки, которые потребуется проверить с ML-командой на размеченных данных.

Сервис распознаёт верхние кадры по наклону камеры или ручной отметке. Стороны фасада `N/E/S/W` автоматически не угадываются: их нужно передать в `views` после проверки ракурсов. Несколько фотографий с неизвестными сторонами могут дать предположение, которое останется на проверке.

Первый надёжный материал сохраняется за объектом. Более поздняя отделка не стирает это значение. Если новая модель предлагает другой материал, система показывает противоречие. Ручная правка сотрудника хранится отдельно от ответа модели и не перезаписывается автоматически.

## Что передать ML-команде

Контракт находится в `schemas/material.py`, интерфейс — `MaterialPredictor` в `agents/material/model.py`.

Адаптер готовой модели получает:

- `image`: RGB-изображение Pillow с уже учтённым поворотом EXIF;
- `image_id`: идентификатор снимка.

Он возвращает список `Observation`: одно наблюдение на область стены. У каждого наблюдения есть:

- `image_id`;
- `visibility`: `visible`, `hidden`, `no_walls` или `unclear`;
- `material`: код материала либо `null`, если он не виден;
- `confidence`: число от 0 до 1;
- `crop_bbox`: `[x1, y1, x2, y2]` в долях ширины и высоты изображения.

Для `visible` обязательны материал и рамка. Скрытой или отсутствующей стене нельзя назначать предполагаемый материал. Даже когда стены не найдены, адаптер должен вернуть наблюдение `no_walls`, если он может это подтвердить; пустой список означает недостаток данных.

Коды материалов: `brick`, `aerated_concrete`, `ceramic_block`, `timber`, `frame`, `sip`, `monolith`. Реальные классы и способ выделения стен согласуем с ML-командой. Внутри адаптера можно соединить детектор стен и классификатор материала: остальной бэкенд от этого не меняется.

У адаптера также есть `version` — версия модели и `is_demo = False`. Функция-фабрика загружает локальные веса один раз при старте воркера и возвращает адаптер.

Когда такой модуль будет готов, в обоих терминалах задайте, например:

```powershell
$env:MOCK = "0"
$env:MATERIAL_MODEL_FACTORY = "ml_adapter:create_model"
```

`ml_adapter:create_model` — пример имени будущего модуля и функции, а не уже реализованная модель. Затем перезапустите API и воркер. Если модель не настроена, её результат будет явно помечен как `model_unavailable`, а причина попадёт в `module_errors`. Второй обработчик продолжит работать. Общая сборка описана в [INTEGRATION.md](INTEGRATION.md).

## Как объяснить на защите

«Мы получаем несколько снимков одного дома и сохраняем их без изменений. Обученная модель ищет материал стен, а наш бэкенд проверяет согласованность ответов на разных фасадах. В результате сотрудник видит материал и фотографии, которые его подтверждают. Если стены закрыты отделкой или данных мало, система сообщает об этом. Сотрудник может проверить и исправить результат, причём исходный ответ модели остаётся в истории».

Для текущего демо добавляем: «Обученная модель пока не подключена. Сейчас показываем работающую загрузку, обработку метаданных, очередь и ручную проверку. Интерфейс подключения модели уже подготовлен».
