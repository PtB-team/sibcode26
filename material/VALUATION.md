# Примерная стоимость постройки · 0.5

## Объяснение для защиты

Модель определяет материал стен и готовность дома. Бэкенд берёт площадь из проекта или ввода сотрудника, выбирает ставку для материала и считает три суммы. GigaChat получает готовые суммы для объяснения в сводке.

```text
Готовый контур = общая площадь × ставка для материала
Выполненная часть ≈ стоимость контура × готовность / 100
Остаток ≈ стоимость контура − выполненная часть
```

Пример: газобетон, 100 м², готовность 40%, ставка 50 000 ₽/м². Получаем 5 млн ₽ для готового контура, 2 млн ₽ для выполненной части и 3 млн ₽ на достройку.

Это упрощение: физический процент готовности условно принят за долю стоимости работ. Реальная стоимость этапов различается. Сумма выполненной части **не подтверждает расходы клиента**. Расчёт **не определяет рыночную или залоговую стоимость** и не запускает банковские решения.

## Демонстрационные тарифы

Тарифы **придуманы для хакатона**, а не взяты из рынка. Конфиг: [configs/valuation.yaml](../configs/valuation.yaml). Комплект работ: условный наружный контур — фундамент, стены, кровля, окна, двери, фасад. Земля, внутренняя отделка, инженерные сети, благоустройство, демонтаж и исправление дефектов в тариф не входят.

| Материал | Демонстрационная ставка, ₽/м² |
|---|---:|
| Кирпич | 60 000 |
| Газобетон / пеноблок | 50 000 |
| Керамический блок | 55 000 |
| Брус / бревно | 48 000 |
| Каркас | 40 000 |
| СИП-панели | 42 000 |
| Монолит | 65 000 |

Округление — до 1 000 ₽. Вилка ±30% — демонстрационный сценарий, не измеренная точность и не доверительный интервал. Настройки, комплект работ, исключения и версия правил находятся в конфиге. При переходе на проверенные тарифы обновите также `version`, `rate_kind` и подпись.

Для объекта можно ввести свою ставку и её источник. Сервис помечает её как ввод сотрудника; происхождение и соответствие комплекту работ нужно проверить. Стоимость земли вводится отдельно и не меняет три суммы постройки.

## Источники данных

| Данные | Приоритет источников |
|---|---|
| Площадь | Ручная `valuation_inputs.area_m2` → `project.total_area_m2` → `project.footprint_m2 × project.floors` |
| Материал | Закреплённый `object.material.observed` → проектный `project.wall_material` с предупреждением |
| Ставка | Ручная `unit_cost_rub_m2` → тариф для материала |
| Готовность | Ручная проверка последнего завершённого облёта → реальная модель со статусом `determined` и `target_confirmed=true` |

Пятно застройки × этажность — приближение по внешнему контуру. При неизвестной этажности один этаж не подставляется. Площадь по обычному фото сейчас не определяется. Для расчёта берётся `readiness_pct`, а не банковская шкала `bank_readiness` 0/50/100.

Без площади или ставки суммы равны `null`, статус `insufficient_data`. Если известна только полная стоимость, статус `partial`: выполненная часть и остаток остаются `null`. При наличии всех данных статус `estimated`. Нулевая готовность допустима: выполненная часть будет 0 ₽. Демонстрационная или неподтверждённая готовность модели в деньги не переводится. Ручная проверка сотрудника работает и без подключённой модели.

## Как проверить

1. Запустите API, воркер и фронт по [INTEGRATION.md](INTEGRATION.md). Выберите режим API.
2. Создайте объект. В дополнительных полях можно указать общую площадь и материал по проекту.
3. Загрузите снимки и дождитесь обработки. Без готовой модели в обзоре нажмите «Исправить» и укажите стадию, готовность и основание проверки. Во вкладке материала можно отдельно закрепить фактический материал.
4. Откройте «Стоимость постройки». При необходимости введите площадь и нажмите «Сохранить параметры и пересчитать».
5. Проверьте суммы, формулу, источники и предупреждения. Пустые поля снимают ручные настройки и возвращают расчёт к данным проекта/конфига.

При исправлении материала или готовности текущий расчёт обновляется при чтении карточки. История сохранённых расчётов остаётся неизменной.

## API

Базовый путь: `/api/v1`.

| Метод | Путь | Результат |
|---|---|---|
| GET | `/objects/{id}/valuation` | Расчёт по текущим данным |
| POST | `/objects/{id}/valuation` | Сохранить параметры и снимок расчёта |
| GET | `/objects/{id}/valuation/history` | Снимки с автором, временем и признаком `stale` |

Пример POST:

```json
{"area_m2": 100, "unit_cost_rub_m2": null, "rate_note": "", "land_rub": null}
```

Все поля необязательны. Отсутствующее поле сохраняет прежнюю настройку, `null` снимает числовую настройку. Пустое тело пересчитывает с прежними параметрами. Площадь и ставка положительны, земля неотрицательна; нечисловые и бесконечные значения отклоняются с HTTP 400. `rate_note` — строка до 1 000 символов. `X-User` задаёт метку автора; аутентификация в прототипе не реализована.

Основные поля ответа для газобетона, 100 м² и готовности 40%:

```json
{
  "estimate_type": "construction_cost",
  "method": "linear_readiness_assumption",
  "status": "estimated",
  "is_demo": true,
  "is_preliminary": true,
  "currency": "RUB",
  "full_cost_rub": 5000000,
  "completed_cost_rub": 2000000,
  "remaining_cost_rub": 3000000,
  "full_range_rub": [3500000, 6500000],
  "completed_range_rub": [1400000, 2600000],
  "remaining_range_rub": [2100000, 3900000],
  "missing_data": []
}
```

Полный ответ включает `breakdown`, `warnings`, `explanation`, версию `rules` и `fingerprint`. POST добавляет `id`, `author`, `calculated_at`. GET не пишет историю. В карточке объекта доступны `valuation` и сохранённые `valuation_inputs`. Денежные поля ответа — числа; сохранённые десятичные параметры могут передаваться строками.

Совместимые поля `value_rub` и `range_rub` содержат выполненную часть с введённой стоимостью земли, если она задана (`value_includes_land`). Это **тоже не рыночная стоимость**. Для нового интерфейса используйте три поля `*_cost_rub`; `collateral_value_rub` этот метод не принимает.

Исторический снимок получает `stale=true`, когда его параметры, исходные данные или тарифы отличаются от текущих. Суммы и источники в нём сохраняются. При ошибке файла тарифов возвращается `configuration_error` без сумм; обработка фотографий продолжает работать.

## Что за что отвечает

- [calculator.py](../agents/valuation/calculator.py) — источники, формула, округление, предупреждения.
- [valuation.yaml](../configs/valuation.yaml) — демонстрационные тарифы и настройки.

В GigaChat уходят суммы, статус, метод, комплект работ и признак демонстрационных тарифов. Свободный текст источника ставки в запрос модели не попадает. Промпт предписывает объяснять рассчитанные суммы с их ограничениями. Сама формула работает без GigaChat.
