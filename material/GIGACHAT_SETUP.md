# GigaChat в бэкенде · 0.4

Сервис отправляет обезличенные факты инспекции в GigaChat и показывает AI-сводку в карточке дома. Запрос выполняется в воркере. Загрузка фото, YOLO и ручные проверки продолжают работать при недоступном API.

## Настройка

Из корня проекта установите зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-backend.txt
```

Откройте локальный `.env`. Если его нет, скопируйте `.env.example`. Файл `.env` исключён из Git. Заполните:

```dotenv
MOCK=0
GIGACHAT_ENABLED=1
GIGACHAT_CREDENTIALS=ваш_Authorization_Key_без_Basic
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
```

Authorization Key — готовая строка из Studio, повторно кодировать её в Base64 не нужно. Для ключа организации выберите соответствующий `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`. Модель должна быть доступна вашему проекту.

Для TLS нужен корневой сертификат НУЦ Минцифры. Можно скачать публичный PEM по адресу из [официальной инструкции](https://developers.sber.ru/docs/ru/gigachat/certificates), без изменения системного хранилища:

```powershell
New-Item -ItemType Directory -Force -Path certs | Out-Null
Invoke-WebRequest -Uri "https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt" -OutFile "certs/russian_trusted_root_ca_pem.crt"
```

В `.env` укажите:

```dotenv
GIGACHAT_CA_BUNDLE=certs/russian_trusted_root_ca_pem.crt
```

Проверка TLS всегда включена. Дополнительный сертификат добавляется к стандартным доверенным корням приложения. Если нужный корень уже доступен системному Python, поле можно оставить пустым.

Проверьте подключение:

```powershell
.\.venv\Scripts\python.exe -m integrations.gigachat --check
```

Команда получает токен и список моделей. Она выводит названия моделей и результат проверки, не печатая ключ и токен. Если выбранной модели нет в списке, измените `GIGACHAT_MODEL`. В `MOCK=1`, при выключенной интеграции или пустом ключе сетевого запроса не будет.

Перезапустите API и воркер по [INTEGRATION.md](INTEGRATION.md). Откройте фронт в режиме API → карточка объекта → «Обзор» → «AI-сводка инспекции».

Настройки `.env` читаются при запуске обоих процессов. Переменные окружения имеют приоритет над файлом. Ключ не передаётся браузеру. Если модели YOLO ещё не подключены, можно вручную подтвердить результаты инспекции и анализировать эти факты через GigaChat.

## Работающие маршруты

| Маршрут | Назначение |
| --- | --- |
| `GET /api/v1/gigachat/status` | Состояние настройки без секретов |
| `POST /api/v1/objects/{id}/analysis` | Создать задание, HTTP 202; тело `{}` или `{"force":true}` |
| `GET /api/v1/objects/{id}/analysis` | Последняя сводка и состояние фактов |
| `GET /api/v1/analyses/{analysis_id}` | Состояние отдельного задания |

`llm_status`: `pending` — ожидается ответ; `accepted` — предложение прошло проверку; `unavailable` — API недоступен или выключен; `rejected` — неверный или устаревший ответ. До первого задания `status: idle`: это не ответ модели.

До принятого ответа показывается вывод по правилам с `decision_source: rules_fallback`, `recommendation: null`. Проверенный ответ имеет `decision_source: gigachat`. При ошибке API работа инспекции не останавливается.

Одинаковые активные запросы объединяются. Готовое принятое заключение используется повторно; `force: true` явно заказывает новую генерацию. Отказ или недоступность можно повторить без `force`. При `GIGACHAT_ENABLED=1` и `GIGACHAT_AUTO_ANALYZE=1` обработанный облёт и ручные правки автоматически создают задания. Отключите автоматический запуск, если хотите использовать только кнопку.

Очередь хранится в SQLite и переживает перезапуск. Зависшее задание доступно после окончания аренды; старый воркер не перезаписывает новое завершение. После трёх прерываний показывается резервный ответ. Если факты изменились до или во время запроса, старая рекомендация не публикуется.

## Какие данные отправляются

Только разрешённые поля: подтверждённая готовность, закреплённый материал и сравнение с проектом, сроки, признаки реестра, сравнение с графиком. ФИО, адрес, кадастровый номер, номер кредита, фотографии, авторы и свободные комментарии не входят в запрос. Поля перечислены в `agents/analysis/context.py`; вся карточка объекта в API модели не отправляется.

Контрольные точки сравниваются со стадией на дату съёмки. При их отсутствии используется явно обозначенное допущение линейного плана: отставание на 10 процентных пунктов требует уточнения. Это начальный порог, а не утверждённая методика банковского риска. Неподтверждённое распознавание не считается установленной готовностью. Старые фотографии требуют обновления, будущая дата — проверки метаданных.

Пример: по подтверждённому облёту возведены только стены, а к этой дате по графику уже должна быть крыша. Код отмечает признак отставания, GigaChat объясняет его и предлагает уточнить ситуацию у клиента. Это работает и при отсутствии просрочки. Причина задержки не выдумывается по фотографии.

## Ограничения

Это предложение сотруднику: `proposal_only: true`. Сервис не отправляет сообщения клиентам и не выполняет кредитные или юридические действия.

Разрешены контрольный облёт (`S1`), мониторинг (`S5`) и шаги проверки/уточнения. Допустимую пару кодов определяют правила до запроса. `S2`, `S3`, `S4`, `S6`, `S7`, `S8` закрыты: подтверждённые исходы общения и полный банковский процесс ещё не реализованы. Возможность `gigachat_analysis` включена отдельно; `capabilities.conductor` и `risk` остаются `false`.

Pydantic проверяет JSON, код проверяет допустимость пары действий, ссылки на факты и список недостающих данных. Это не гарантирует безошибочность свободного текста: сотрудник видит факты отдельно и проверяет предложение.

Для аудита сохраняются обезличенный контекст, версии правил и промпта, исходный ответ, результат проверки, модель и статистика токенов. Отклонённый текст не выдаётся публичным API. HTTP-ошибки сохраняются безопасными кодами и сообщениями, без тела ответа авторизации.

## Основные файлы

| Где | Для чего |
| --- | --- |
| `integrations/gigachat/` | Настройки, OAuth, HTTPS, токен в памяти, команда проверки |
| `agents/analysis/context.py` | Факты и разрешённые действия |
| `agents/analysis/service.py` | Вызов, проверка, резерв и устаревшие ответы |
| `api/analysis_database.py` | Очередь и аудит |
| `schemas/analysis.py` | Формат ответа |
| `front/js/analysis.js` | Отображение сводки |

Для защиты: «YOLO определяет, что видно на снимках. Бэкенд проверяет данные и сравнивает их с планом. GigaChat получает подготовленные факты и объясняет, на что обратить внимание. Код проверяет предложенный шаг, а решение принимает сотрудник».

Протокол сверён с официальными [авторизацией](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api), [получением токена](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token) и [структурированным выводом](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output). Реализация использует `/v1/chat/completions` с `response_format.schema` и `strict: true`.
